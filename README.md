## 可以做什么

| 功能 | 使用方式 |
| --- | --- |
| **主程序 + 插件架构** | 主程序统一管理账户与工作区，直播工作台、直播助手、桌宠联动按需使用，支持独立安装、启停、更新和回滚。 |
| **插件与更新** | 在一个页面检查主程序与插件更新，一键更新已安装插件并下载主程序更新，逐项查看进度与结果。 |
| **四平台直播工作台** | 同时接入哔哩哔哩、抖音、快手和视频号，在同一工作台查看各平台连接状态，以及收到的弹幕和礼物消息。 |
| **特定礼物规则** | 为指定平台与礼物设置反馈，按单次送礼、连送或累计数量触发效果，并管理等待队列。 |
| **全局礼物特效** | 为其他礼物配置通用反馈，通过 OBS Studio 礼物互动源展示通知、礼物雨、爱心成形等效果。 |
| **模型碰撞与自动接入** | 复用 VTube Studio 模型画面，自动准备 OBS 来源与礼物碰撞；有歧义时选择并记住，保留已有布局与规则。 |
| **常驻礼物、节目与计时** | 管理常驻礼物展示、礼物对应的节目待办和倒计时，支持暂停、撤销及独立 OBS 输出。 |
| **声音与现场控制** | 使用弹幕朗读、欢迎与礼物感谢、音效台和点歌队列，调整声音、暂停或跳过播放。 |
| **直播助手** | 查看互动提醒、话题建议、礼物节目安排、投票和本场复盘，由主播决定是否采纳与执行。 |
| **开播准备** | 保存平台与出镜方式，检查并启动 OBS Studio、平台直播工具等本机软件，减少重复准备。 |
| **桌宠联动** | 管理角色与 Live2D 模型，为同一角色添加、选择和独立命名多款模型，明确发布后分享给粉丝。 |
| **个人中心与语言** | 管理账户头像和名字、使用邮箱验证码登录或绑定账户；支持简体中文与 English 界面切换。 |

四个平台可以同时连接；各平台提供的消息种类、字段与投递情况不同，实际显示以平台返回和客户端连接状态为准。各平台需分别完成房间或登录配置。FurryUP Studio 聚合收到的互动消息，正式推流仍需在对应平台软件中确认。

### 一个主程序，按需使用插件

FurryUP Studio 采用**主程序 + 独立插件**架构：主程序提供统一的账户、工作区与插件管理，直播工作台、直播助手和桌宠联动分别承担各自的功能。常规插件更新可以独立完成，无需每次重新安装整个主程序。

新版**插件与更新**将更新总览和主程序更新放在页面顶部，下面集中管理各个插件。点击“检查全部更新”查看可用版本，或点击“一键更新全部”，依次更新已有插件并准备主程序安装包。主程序下载并校验完成后，点击“退出并安装”完成升级；安装前保留 OBS Studio 直播与录制状态检查。

每个更新项目都有独立状态；个别插件失败时继续处理其余项目，可查看原因后重试。更新保留已验证的旧版本与已有的停用、卸载选择，不自动安装未安装的插件或启用已停用的插件。直播助手和消息采集独立运行，更新或停用助手不会中断直播工作台接收消息。

### 礼物互动与模型碰撞系统

**让观众送出的礼物，成为角色直播画面中的互动。**

FurryUP Studio 将礼物规则、视觉反馈和模型碰撞放在同一个直播工作台中。主播可以决定哪些礼物触发效果、达到多少数量开始播放，以及是否让礼物雨与正在出镜的模型发生碰撞。

| 系统 | 主播可以配置什么 |
| --- | --- |
| **礼物互动** | 特定礼物与通用规则、单次或连送数量门槛、通知和礼物雨、雨后爱心，以及音效与语音感谢。 |
| **模型碰撞** | 从 VTube Studio 获取选定部位的实时轮廓，让礼物雨沿模型轮廓弹开或滑落，并与 OBS 中的模型画面对齐。 |
| **自动接入** | 共用 VTube Studio 输入与碰撞准备流程；能唯一确定的来源自动复用，无法确定时选择一次并记住。 |

使用流程是 **准备连接与模型 → 保存并启用礼物规则 → 本地验证 → 接收直播礼物**。准备连接与启用规则分别控制，主播保留对实际播放的决定权。

**公开范围：本节提供功能介绍与使用说明。礼物互动系统和模型碰撞系统的核心源码暂不公开，自制特效、业务规则实现、模型映射与专属素材保持私有。** 已单独开源的组件以各自仓库说明为准。

直播控制台集中显示平台状态、最近弹幕、朗读队列、点歌和礼物互动。针对特定礼物设置规则后，可以安排对应的通知或动画；其他礼物使用通用规则。礼物视觉反馈、音效与语音感谢分别配置，可按直播需要启停。

将礼物互动源添加到 OBS Studio 的浏览器源后，可显示礼物通知、礼物雨和爱心效果。画面与触发数量按规则配置；本地预览使用示例数据，正式反馈依据实际收到的礼物事件。外部直播软件需事先安装和配置，开播前请确认画面、模型、音频和推流设置。

例如，内置规则可按“同一观众连送满 10 份播放礼物雨、满 520 份雨后拼爱心”反馈礼物，也可修改或停用。新增推荐支持填入草稿后保存，或一键添加为停用规则，再由主播确认启用。“全局”表示可为全部平台或全部礼物配置通用反馈，不会跨平台混合计数；同一观众连送按平台、房间、观众与礼物种类分别统计。

在主窗口「插件与更新 → 内容更新 → 礼物互动内容包」统一检查与更新特效及推荐规则。礼物页将夜霜官方与第三方精选分开，支持预览和一键添加；内容更新不会覆盖已保存规则。符合现有播放接口的新增特效无需再次升级工作台插件。

### 自动接入 VTube Studio 与模型碰撞

在礼物互动页点击“自动接入并准备碰撞”，程序会检测连接、识别可用模型输入并复用 OBS 场景。无法唯一确定来源时再让你选择，并记住结果。礼物触发条件与特效仍统一在礼物规则中设置，准备连接不会替你启用规则。

VTube Studio／VBridger 继续驱动模型，OBS Studio 负责最终合成。碰撞使用 VTube Studio 提供的实时轮廓，需要当前 VTube Studio 版本支持对应接口；不支持时会提示，程序不会自动切换其版本。新模型的碰撞部位可能需要选择一次。本功能使用轮廓近似碰撞，不是柔体模拟。

开启碰撞的礼物雨会逐个落下、弹开或滑落。以 520 份礼物为例，同屏默认最多 80 个，其余继续排队，全部离场后再开始爱心。模型与特效的对齐沿用当前场景设置，已有礼物规则不自动改写。升级后请留意工作台中的 OBS 页面更新提示，并在开播前本地验证。

**使用条件与验证范围（2026-10-26）：** 需要安装并配置 OBS Studio、支持实时轮廓接口的 VTube Studio，以及相应平台的房间或登录信息。首次 API 授权、无法识别的模型部位和有歧义的来源需要主播确认；碰撞依据所选部位的轮廓范围工作，不会自动理解所有模型结构。目前支持礼物雨的轮廓碰撞，四面抛掷、按命中部位触发受击动作尚未提供。

当前介绍对应主程序 **0.15.0 / 工作台 0.26.0**。已完成本地与隔离环境检查，长时实播及不同设备环境仍在验证；启动、窗口恢复与部分哔哩哔哩礼物触发问题正在继续排查和修复，相关后续修复尚未随现有公开版本发布。请先完成本地试播，再用于正式节目。

### 让助手整理信息，保留自己的节奏

直播助手提供实时建议与复盘入口。建议先展示给主播；问题和投票需由主播明确采纳或开始后才进入 OBS Studio。在线建议需要主动发起，并使用本机已登录 Codex 账户的可用额度。停止助手不会中断直播工作台的消息采集，原有记录继续保留。

视频号会尝试复用本机保存的登录状态；登录过期或平台要求验证时，仍需重新扫码。联网语音需要网络连接，在线点歌需要配置兼容的音乐服务。

### 把角色陪伴延续到直播之外

主播与角色创作者使用 FurryUP Studio 管理角色和模型，准备好后再明确发布或同步给粉丝。粉丝使用独立的 **FurryUP 桌宠**，通过分享链接确认下载，并在自己的桌面上选择角色模型。两端分别安装、分别更新。

启动软件或恢复会话不会自动发布本机模型。公开分享前需要连接账户，并确认拥有模型及相关素材的分发权限。

## 本次更新 · 0.15.0

- **自动准备模型碰撞：** VTube Studio 输入与礼物碰撞共用准备流程，自动识别并复用可确定的 OBS 来源；多个候选时选择一次并记住。首次连接授权与无法识别的模型部位仍由用户确认。
- **保留现有直播配置：** 复用已有场景和来源，保留模型位置、缩放、裁剪、可见性及礼物规则；自动恢复连接，提示 OBS 页面版本并在适当时更新。
- **逐个碰撞礼物雨：** 按礼物规则触发，让礼物落到模型轮廓上弹开或滑落。520 份礼物逐个生成，同屏默认最多 80 个，全部离场后再播放爱心；修复轮廓变化误清空礼物的问题。
- **礼物与节目安排：** 增加常驻礼物、单次通知随机大小、节目待办和可增减时间的倒计时；推荐支持预览和选择，内容更新保留已保存规则。
- **观众头衔：** 四平台展示能够明确获取的房管、守护、粉丝牌与等级信息，补充抖音星守护及快手扩展头衔识别，减少重复显示。
- **主程序与配套插件：** 首页视觉与设置布局更新；主程序、直播助手、桌宠及投屏预览支持跟随系统语言，保留手动语言选择。
- **版本组合：** 主程序 0.15.0；直播工作台 0.26.0；直播助手 0.8.1；桌宠联动 0.6.1；iPhone 投屏预览 0.5.2。公开投屏预览不含原生接收器，接收功能暂不可用。
